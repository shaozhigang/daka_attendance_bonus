# 需求：统计页手动修改打卡状态

> 版本：v1.0 · 2026-09-09  
> 关联页面：统计（`/stats`）  
> 关联方案：[plan-b-pwa-dashboard.md](./plan-b-pwa-dashboard.md) §5.2

---

## 1. 背景与问题

App 通过「我已打卡」确认来记录每日上下班状态。实际使用中会出现以下情况：

- 用户已在**企业微信**完成打卡，但忘记在 App 内点确认
- 22:00 兜底审计将当天标记为「漏打」，与实际打卡情况不符
- 用户事后对账时，需要在统计页修正个别日期的状态

当前统计页日历为**只读**，无法修正误标记，导致全勤统计、连续天数、奖金进度等数据不准确。

---

## 2. 目标

在统计页日历上，允许用户对**历史及当天**的工作日手动修正打卡状态，使本地记录与企业微信实际打卡情况保持一致。

---

## 3. 用户故事

**作为**需要全勤奖的员工，**我希望**在统计页点击某一天并修改其打卡状态，**以便**纠正因忘记 App 确认而产生的误标记。

---

## 4. 功能需求

### 4.1 触发方式

| 编号 | 描述 |
|------|------|
| F-01 | 用户点击统计页月历中的某个日期格，弹出状态编辑面板 |
| F-02 | 仅**工作日**（周一至周五）且**非未来日期**可点击编辑 |
| F-03 | 周末、未来日期点击无响应（或轻提示「不可编辑」） |

### 4.2 可选状态

与现有图例一致，共 4 种：

| 状态 | 标识 | 含义 |
|------|------|------|
| 正常 | `normal` | 上下班均已打卡（含事后补记） |
| 补卡 | `makeup` | 当日通过补卡流程完成 |
| 漏打 | `missed` | 当日有遗漏，未完整打卡 |
| 休息 | `rest` | 请假/调休/无需出勤 |

### 4.3 状态编辑面板

| 编号 | 描述 |
|------|------|
| F-04 | 面板展示：日期（如「9月3日 周三」）、当前状态 |
| F-05 | 提供 4 个状态选项按钮，当前选中项高亮 |
| F-06 | 选择后立即保存并关闭面板，日历颜色实时更新 |
| F-07 | 面板底部说明：「修正仅影响本 App 统计，请以企业微信记录为准」 |

### 4.4 数据持久化

| 编号 | 描述 |
|------|------|
| F-08 | 修改结果写入 `localStorage`（复用现有 `daka-records`） |
| F-09 | 手动修改的记录标记 `manualOverride: true`，防止 22:00 兜底审计覆盖用户修正 |
| F-10 | 设为「正常」时，同步将 `clockIn`、`clockOut` 设为已确认 |

### 4.5 统计联动

修改后以下数据**自动重算**（无需额外操作）：

| 编号 | 描述 |
|------|------|
| F-11 | 统计卡片：全勤 / 补卡 / 漏打 天数 |
| F-12 | 全勤率百分比 |
| F-13 | 首页：全勤奖金进度、连续全勤天数 |

---

## 5. 交互流程

```
统计页 → 点击日历某日（工作日、非未来）
      → 弹出状态编辑面板
      → 选择目标状态（正常/补卡/漏打/休息）
      → 保存至 localStorage
      → 面板关闭，日历 + 统计卡片刷新
```

---

## 6. 边界与约束

| 场景 | 行为 |
|------|------|
| 点击周末 | 不可编辑 |
| 点击未来工作日 | 不可编辑 |
| 点击当天（pending 灰色） | 可编辑，允许提前标记休息或补卡 |
| 无记录的历史工作日（显示红色漏打） | 可编辑，创建新记录 |
| 手动改为「正常」 | 写入 confirmed 标记，计入全勤 |
| 手动改为「漏打」 | 不计入全勤，计入漏打 |
| 22:00 审计 | 跳过 `manualOverride: true` 的记录 |

---

## 7. 非目标（Out of Scope）

- ❌ 修改企业微信实际打卡记录
- ❌ OCR 截图导入（见 plan-b 远期规划）
- ❌ 跨月切换（当前仅展示当月，保持现状）
- ❌ 撤销/历史修改日志

---

## 8. 验收标准

- [ ] 点击历史漏打日期，改为「正常」后，日历变绿、漏打计数减少、全勤计数增加
- [ ] 点击历史正常日期，改为「补卡」后，日历变黄、补卡计数增加
- [ ] 修改后刷新页面，状态保持不变
- [ ] 手动修正的日期不会被 22:00 审计改回漏打
- [ ] 周末和未来日期无法编辑
