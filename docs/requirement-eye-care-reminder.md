# 用眼提醒功能 · 产品需求文档

> 在全勤守护（Daka）中增加「用眼健康提醒」，帮助日常办公用户建立可持续的屏幕用眼节奏，降低视疲劳与干眼风险。

---

## 一、背景与问题

### 1.1 用户场景

| 维度 | 说明 |
|------|------|
| 典型用户 | 办公室职员，长时间面对电脑/手机 |
| 工作时段 | 约 08:50–18:15（与本 App 考勤时段一致） |
| 实际用眼 | 连续盯屏 1–2 小时不休息极为常见 |
| 现有痛点 | 知道要休息，但忙起来完全忘记；没有轻量、可执行的提醒工具 |

### 1.2 健康背景（专业结论）

办公用眼属于**近距离、长时间、低眨眼频率**的高负荷场景。权威机构与眼科共识可归纳为：

| 原则 | 来源/依据 | 核心建议 |
|------|-----------|----------|
| **20-20-20 法则** | 美国验光协会（AOA）等广泛推荐 | 每 **20 分钟**，看 **6 米（约 20 英尺）外** 物体 **20 秒** |
| **每小时休息** | 职业安全与眼保健通用建议 | 每 **50–60 分钟** 连续近距用眼后，休息 **5–10 分钟** |
| **眨眼与湿度** | 干眼症研究 | 专注屏幕时眨眼频率可下降 50%+，需有意识增加眨眼、远眺 |
| **累积效应** | 全天连续用眼 | 单次短休不够，需「微休息 + 短休息 + 午间长休息」组合 |

**结论（产品默认值依据）：**

- **微休息（主推）**：每 **20 分钟** 提醒一次，休息 **20 秒～2 分钟**（对应 20-20-20）
- **短休息（辅助）**：每 **50 分钟** 提醒一次，休息 **5～10 分钟**（起身、远眺、补水）
- **长休息（已有）**：午休 **30～60 分钟** 远离屏幕（App 不强制，可配置静默时段）

> 为什么不建议「每 60 分钟才提醒一次」作为唯一策略？  
> 对多数程序员/文案/设计岗位，60 分钟内往往已出现酸胀、干涩；20 分钟微休息成本极低，依从性更好。50 分钟短休息作为「加强版」可选开启。

## 二、产品定位

| 维度 | 说明 |
|------|------|
| 功能名 | 用眼守护 / Eye Break |
| 在 App 中的角色 | **考勤之外的第二守护线**——全勤守护钱包，用眼守护健康 |
| 与打卡提醒关系 | **互补、不冲突**：打卡按固定时刻；用眼按「连续用眼计时」或「周期计时」 |
| 形态 | 复用 PWA 通知 + 可选页面内轻提示；与方案 A 日历可并行 |
| 目标 | 让用户「被温柔地打断」，而不是被骚扰 |

## 三、用户故事

1. **作为** 长时间盯屏的上班族，**我希望** 每 20 分钟收到一次轻提醒，**以便** 养成远眺习惯，减少眼睛酸胀。
2. **作为** 用户，**我希望** 开会或演示时能一键暂停，**以便** 提醒不会在 inappropriate 时刻弹出。
3. **作为** 用户，**我希望** 点「已完成休息」后计时重置，**以便** 系统知道我真的休息了，而不是单纯关通知。
4. **作为** 用户，**我希望** 看到今日完成了多少次用眼休息，**以便** 有正向反馈、愿意坚持。
5. **作为** 用户，**我希望** 午休和下班后的提醒自动停止，**以便** 不被无意义打扰。

## 四、提醒策略设计（核心）

### 4.1 推荐默认策略：**20 + 50 双层节奏**

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 2 · 短休息（可选，默认关闭）                          │
│  每 50 分钟 → 提醒休息 5 分钟 → 起身 / 远眺 / 喝水           │
├─────────────────────────────────────────────────────────────┤
│  Layer 1 · 微休息（默认开启）                                │
│  每 20 分钟 → 提醒远眺 20 秒～2 分钟 → 看 6 米外 + 多眨眼     │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 时间参数表

| 策略 | 连续用眼/周期间隔 | 建议休息时长 | 默认 | 适用场景 |
|------|-------------------|--------------|------|----------|
| **微休息** | **20 分钟** | **20 秒～2 分钟** | ✅ 开启 | 日常办公、编码、文档 |
| **短休息** | **50 分钟** | **5～10 分钟** | ☐ 关闭 | 深度工作块、设计/剪辑 |
| **长休息** | 120 分钟 | 15 分钟 | ☐ 关闭 | 可选；易与午休重叠 |
| **20-20-20 严格模式** | 20 分钟 | 固定 20 秒倒计时 | 微休息子选项 | 希望严格执行 AOA 建议 |

### 4.3 与办公节奏的映射（示例：08:50–18:15）

假设 12:00–13:30 午休静默：

| 时段 | 微休息（20 min）约次数 | 短休息（50 min）约次数 |
|------|------------------------|------------------------|
| 上午 08:50–12:00 | ~9 次 | ~3 次 |
| 下午 13:30–18:15 | ~14 次 | ~5 次 |
| **全天合计** | **~23 次** | **~8 次** |

> 产品文案可展示：「今日已护眼 12/23 次」—— 用完成率激励，而非惩罚漏做。

### 4.4 静默时段（默认）

| 时段 | 行为 |
|------|------|
| 12:00–13:30 | 不发送用眼提醒（午休） |
| 18:15 之后 | 不发送（下班） |
| 周末 | 默认不提醒（可设置中开启） |
| 用户手动「暂停 N 分钟/今日暂停」 | 立即停止并重置计时 |

## 五、提醒内容与交互

### 5.1 通知文案（微休息）

| 节点 | 标题 | 正文 |  urgency |
|------|------|------|----------|
| 到点 | 👁️ 该让眼睛歇一下了 | 看看 6 米外的物体，眨眼 10 次，约 20 秒 | 普通 |
| 未确认 +2 min | 👁️ 还在忙吗？ | 20 秒远眺即可，眼睛会感谢你 | 普通 |
| 未确认 +5 min | ⚠️ 用眼超时 | 已连续盯屏较久，请至少休息 1 分钟 | 强提醒（可选震动） |

### 5.2 通知文案（短休息，50 min）

| 节点 | 标题 | 正文 |
|------|------|------|
| 到点 | 🌿 起来走一圈 | 已连续用眼 50 分钟，建议休息 5 分钟：远眺 + 喝水 + 活动肩颈 |
| 完成 | ✅ 休息完成 | 计时已重置，继续加油 |

### 5.3 确认闭环（与打卡逻辑对齐）

```
开始计时（用户开启功能 / 上次确认后）
  → 到达间隔 → 推送通知
      ├─ 用户点击「已完成休息」→ 记录一次完成 → 重置计时
      ├─ 用户点击「稍后 5 分钟」→ 推迟一次，不记完成
      └─ 超时未操作 → 可选升级提醒（最多 2 次，避免轰炸）
```

**设计原则：** 不强制倒计时锁屏；降低摩擦，20 秒也能完成。

### 5.4 App 内轻量 UI（首页卡片）

```
┌─────────────────────────────────────────┐
│  👁️ 用眼守护              [ 暂停 30 分 ] │
├─────────────────────────────────────────┤
│  下次提醒：还有 12 分 30 秒              │
│  今日已完成：8 / 20 次微休息             │
│  [ 我休息了，重置计时 ]                  │
└─────────────────────────────────────────┘
```

## 六、功能清单与优先级

### P0 — MVP

| 功能 | 描述 | 验收标准 |
|------|------|----------|
| 开关 | 设置页「用眼提醒」总开关 | 关闭后无任何用眼通知 |
| 微休息 20 分钟 | 默认策略 | 到点收到通知；确认后重置 |
| 静默时段 | 午休 + 下班后 + 周末 | 静默内不触发 |
| 暂停 | 暂停 30 分 / 暂停到明天 | 立即生效 |
| 今日计数 | 完成次数 localStorage | 首页或设置页可查看 |

### P1 — 增强

| 功能 | 描述 |
|------|------|
| 短休息 50 分钟 | 可选第二层提醒 |
| 自定义间隔 | 15 / 20 / 30 / 45 / 50 分钟预设 |
| 20 秒倒计时页 | 全屏温和动画 + 「看远处」提示 |
| 周统计 | 本周完成率、最佳连续达标日 |
| 与考勤联动 | 仅在「已上班确认 ~ 下班前」时段提醒（可选） |

### P2 — 可选

| 功能 | 描述 |
|------|------|
| 健康冷知识 | 通知附带一条护眼 tip 轮换 |
| Apple Watch / 日历同步 | 导出为日历重复事件（方案 A 扩展） |
| 番茄钟整合 | 25+5 与 20+20 二选一主题 |

## 九、技术要点（与现有架构对齐）

| 项 | 方案 |
|----|------|
| 计时 | 前端 `setInterval` + `lastBreakAt`；App 打开时校准 |
| 通知 | 复用 `useNotifications`；新增 `EYE_CARE_SLOTS` 或独立 hook |
| 存储 | localStorage / 与 attendance 同库 |
| SW 后台 | 与打卡相同限制：iOS PWA 弱 → 文档提示用户保持 App 前台或配日历 |
| 与打卡冲突 | 不同 localStorage key；通知 title 区分「⏰ 打卡」与「👁️ 护眼」 |

| 指标 | 目标（上线 4 周后自评） |
|------|-------------------------|
| 功能开启率 | 设置开启用眼提醒的用户 ≥ 80%（单用户即本人） |

## 十一、风险与对策

| 风险 | 对策 |
|------|------|
| 提醒太频烦 | 默认仅 20 min 一层；短休息默认关；可推迟 |
| 开会打断 | 「暂停 30 分」入口放在首页卡片 |
| 后台计时不准 | 以 `lastBreakAt` 绝对时间差计算，而非纯计数 interval |
| 与打卡通知混淆 | 图标/标题/文案体系分离 |
| 用户不做休息只点确认 | 可接受；P1 可加 20 秒倒计时 gentle nudge |

---

## 十二、专业建议摘要（给产品/用户的一句话）

> **日常办公建议：每 20 分钟微休息 20 秒～2 分钟（看 6 米外 + 多眨眼）；每 50～60 分钟短休息 5～10 分钟（起身活动）。**  
> Daka 默认采用 **20 分钟微休息**，可选开启 **50 分钟短休息**，与全勤提醒共用同一 App，但独立开关、独立计时。
